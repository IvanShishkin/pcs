# Пример: интернет-магазин «Витрина»

Концептуальный пример применения PCS к вымышленному продукту. Продукт, компоненты,
случай и свидетельства придуманы, но форма каждого артефакта и распределение статусов
в матрице соответствия взяты с первой реальной реализации: там, где реализация
обычно получает `partial` или `fail`, пример это показывает, а не рисует всё
зелёным.

Пример показывает форму свидетельств. Он не подтверждает соответствие какой-либо
системы: подтверждение возможно только по реальным артефактам.

## Состав

| Файл | Содержание | Раздел методологии |
|---|---|---|
| [plant.md](plant.md) | граница plant, иерархия setpoints, safety invariants | 4 |
| [sensors-actuators.md](sensors-actuators.md) | реестр sensors и каталог операций с policy допуска | 3.3, 5.2, 5.6, 7 |
| [case.md](case.md) | один случай через все восемь обязанностей цикла | 5, 10 |
| [conformance.md](conformance.md) | матрица соответствия на все требования | 15 |

Model в примере сведена к `plant.md` и `sensors-actuators.md`. Остальные части
model, на которые ссылается случай (`failure-modes.md`, решения), не приводятся.

## Продукт

«Витрина» — интернет-магазин: витрина с каталогом, оформление заказа, оплата через
внешнего платёжного провайдера, передача оплаченных заказов на склад. Один арендатор,
одна продуктивная среда. Controller работает при операторском тактировании: оператор
открывает случай в сессии и является supervisory level.
