# Матрица соответствия «Витрины»

Требования: [docs/conformance.md](../../docs/conformance.md). Статусы `pass`,
`partial`, `fail`, `not-applicable`. Свидетельства ссылаются на файлы примера и
показывают, какой артефакт подтверждал бы требование в реальной системе;
подтверждением соответствия они не являются.

Распределение статусов соответствует первой реализации после нескольких реальных
случаев: техническое ядро цикла выполняется, регламентные и измерительные
требования выполняются частично.

| Идентификатор | Статус | Свидетельство |
|---|---|---|
| `PCS-BND-001` | pass | `plant.md`: компоненты, среды, хранилища с классами данных, неуправляемые зависимости, внешние стороны |
| `PCS-SET-001` | pass | `plant.md`: пять уровней, измеримые SLO и окна, режим деградации, порядок разрешения конфликтов |
| `PCS-SAF-001` | partial | S1, S2, S4 проверяются технически (права роли, отсутствие операций); S3 и S5 только процедурно, через содержание случая и плана |
| `PCS-MOD-001` | pass | model в git; каждый файл со строкой «Источник / Актуально до»; случай ссылается на конкретные утверждения model |
| `PCS-SEN-001` | pass | case.md, Sense: таблица свидетельств с источником, средой, областью, состоянием получения; свидетельство 03 зафиксировано как `partial` |
| `PCS-SMP-001` | pass | case.md, Sense и Verify: число элементов и полнота у каждой выборки; `truncated` для логов не выдано за чистый период |
| `PCS-TST-001` | partial | `sensors-actuators.md`: способ проверки у каждого sensor и операции, проба чувствительности выполнена после создания метрики; периодичность не установлена, interlocks ролей повторно не проверялись |
| `PCS-DEC-001` | pass | case.md, Decide: план с целью, альтернативами, классификацией, предусловиями и постусловиями; хэш плана в разрешении, изменённый план отклоняется |
| `PCS-AUT-001` | pass | case.md, Authorize: `plan.auth.yaml` с идентичностью оператора, хэшем плана, сроком действия; запись `authorize` в аудите с идентификатором случая |
| `PCS-EXE-001` | pass | `sensors-actuators.md`: у каждой операции идемпотентность либо правила повтора и частичного исполнения; лимиты попыток и времени исполняются технически |
| `PCS-VER-001` | pass | case.md, Verify: полный перечень постусловий и применимых safety invariants, у каждого sensor, область и исход |
| `PCS-VER-002` | pass | case.md, Verify: P4 `not-checked` оставил случай открытым до раунда 2; P3 принят как остаточный риск постусловия, не safety invariant |
| `PCS-EVO-001` | partial | `plant.md` содержит карту компонентов и зависимостей; правило определения потребителей записано, ни один случай `evolve` через него не прошёл |
| `PCS-LRN-001` | pass | case.md, Learn: исход «model обновлена» с изменениями в `plant.md` и `failure-modes.md`, задача на sensor в очереди |
| `PCS-HIS-001` | pass | case.md, Learn: опровергнутое утверждение о повторах провайдера заменено, прежняя формулировка и свидетельство в истории изменений |
| `PCS-AUD-001` | pass | записи `authorize`, `attempt`, `effect` с идентификатором случая, номером плана, параметрами и идентификаторами эффектов; целостность цепочки проверяется командой |
| `PCS-DRF-001` | partial | сверка model выполняется регламентно при закрытии случая и доводится до исхода (case.md, Learn); автоматического обнаружения расхождений нет |
| `PCS-INV-001` | partial | `sensors-actuators.md`: реестр sensors и операций с владельцем и способом проверки; версия или конфигурация механизма не фиксируется |
| `PCS-CPY-001` | not-applicable | один экземпляр PCS, копий model и механизмов нет |
| `PCS-RDY-001` | partial | case.md, Authorize: срок действия учётных данных проверен перед исполнением; доступность каналов проверяется только для sensors, для actuators — по факту первой попытки |
| `PCS-BRG-001` | partial | `sensors-actuators.md`, аварийный доступ: процедура и обязательный последующий случай описаны; команды записи события `breakglass` в журнал нет, событие вносит оператор вручную |
| `PCS-MET-001` | partial | loop latency, доля успешных действий и вмешательства человека считаются вручную по закрытым случаям; обращения к аварийному доступу не подсчитываются, событие `breakglass` вносится вручную (см. `PCS-BRG-001`) |
