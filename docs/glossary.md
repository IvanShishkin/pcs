# Глоссарий Product Control System

Термины, перечисленные ниже, являются каноническими и употребляются на английском во всех
документах PCS. Все прочие понятия излагаются по-русски. Значения задаются в контексте
методологии и не исчерпывают значений этих терминов в исходных дисциплинах.

## Термины теории управления

| Термин | Значение в PCS |
|---|---|
| **plant** | Объект управления: программный продукт, а также среды, данные и зависимости, явно включённые в границу |
| **controller** | Регулятор: агент и механизмы планирования и проверки правил, принимающие решение о воздействии |
| **model** | Внутреннее представление plant в controller; содержит знание, необходимое для оценки состояния и выбора воздействия |
| **sensor** | Канал получения свидетельств о состоянии plant |
| **actuator** | Типизированный способ воздействия на plant и его окружение |
| **setpoint** | Иерархия желаемых состояний, целей и допустимых диапазонов |
| **process variable estimate** | Оценка состояния plant, восстановленная по свидетельствам |
| **disturbance** | Изменение plant, не являющееся результатом текущего плана воздействия |
| **error** | Рассогласование: расхождение между setpoint и оценкой состояния plant |
| **policy** | Правила допустимости выбора, авторизации и исполнения действий |
| **interlock** | Технически принудительное условие, блокирующее конкретное действие |
| **safety invariant** | Условие, сохраняемое независимо от текущего setpoint и не отменяемое подтверждением человека |
| **supervisory level** | Внешний уровень управления: задаёт setpoint, policy и пределы полномочий |
| **sampling** | Тактирование: моменты, в которые controller получает свидетельства и принимает решение |
| **loop latency** | Время от появления значимого сигнала до проверенного результата воздействия |

## Операционные термины

Употребляются на английском ввиду отсутствия устойчивого русского эквивалента.

| Термин | Значение в PCS |
|---|---|
| **failure mode** | Известный класс отказа plant, для которого определяется стратегия воздействия |
| **SLO** | Целевой уровень качества службы, входящий в иерархию setpoints |
| **error budget** | Допустимый объём отклонений от SLO за период |
| **progressive exposure** | Постепенное раскрытие изменения на часть трафика или пользователей |
| **break-glass** | Аварийное полномочие: временное, ограниченное по области, полностью аудируемое |
| **least privilege** | Минимально необходимые права доступа |
| **dual control** | Требование подтверждения действия двумя лицами |
| **separation of duties** | Разделение обязанностей между исполнителями критической операции |
| **prompt injection** | Внедрение инструкций агенту через данные, которые он читает |
| **human-in-the-loop** | Режим надзора, при котором человек подтверждает действия |
| **human-on-the-loop** | Режим надзора, при котором человек наблюдает и вмешивается по исключениям |
| **sandbox** | Изолированное окружение исполнения, ограничивающее ущерб от действий агента |
| **workspace** | Рабочий контекст исполнителя; не тождествен sandbox |
| **agent control plane** | Плоскость управления парком агентов: их идентичность, policy, развёртывание, наблюдаемость |
| **reconciliation** | Непрерывная сверка заданного состояния с наблюдаемым и устранение расхождения |

## Локальные термины PCS

Термины, введённые настоящей методологией. Не являются общепринятой отраслевой
терминологией:

- **Product Control System (PCS)** — класс систем, определяемый методологией;
- **операторское тактирование** — режим, в котором sampling задаётся сессией оператора;
- **автономное тактирование** — режим, в котором sampling задаётся событием, очередью или
  расписанием;
- **итог обучения** — обязательный исход фазы Learn (см. методологию, 5.8);
- **типы воздействий** `communicate`, `runtime`, `data`, `release`, `evolve` —
  классификация воздействий по содержанию (см. методологию, 5.6);
- **восемь обязанностей цикла PCS** — Model, Sense, Estimate, Decide, Authorize, Execute,
  Verify, Learn.

Если локальный термин впоследствии заменяется признанным отраслевым, глоссарий и матрица
соответствия обновляются совместно.
